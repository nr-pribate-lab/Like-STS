# P0 残項目

P0のうち、静的配信用ビルドの安全な再生成は対応済みです。残る項目を、この文書で管理します。

## 対応済み

- [x] `build.ps1` は必要な入力ファイルと出力先を確認してからビルドする。
- [x] 配信物を一時ディレクトリで組み立て、完了後に `dist/` と入れ替える。組み立てに失敗した場合は既存の `dist/` を残す。
- [x] `.git` などの管理情報、隠しファイル、Markdownの開発文書を含めず、コンテンツ内のJavaScriptと画像・音声・フォントなどの配信用拡張子だけを含める。
- [x] 出力先が通常の `dist/` ディレクトリであることを確認し、別の場所やリンク先を誤って削除しない。コンテンツ内のリンクも拒否する。

## 残っている項目

### コンテンツ定義と検証

- [ ] キャラクター定義で必須にする項目と、初期デッキ・初期レリックの参照方法を確定する。
- [ ] MVPで使うカード効果IDとパラメーター、対象値を一覧にする。複数敵向けの対象など、未実装の値は実装時期を分けて記載する。
- [ ] 起動時に検証する必須項目、型、列挙値、数値範囲を決める。
- [ ] 必須項目の不足、重複ID、未定義効果ハンドラー、存在しない参照先を起動エラーにする。
- [ ] 現在の `src/boot.js` の検証範囲を上記ルールに合わせて拡張する。現状は主にID重複、ステージから地点・敵への参照、初期デッキからカードへの参照を検証している。

### コンテンツ追加手順

- [ ] キャラクター、カード、敵、レリック、ステージを追加する手順と、マニフェストへの登録方法を文書化する。
- [ ] 定義サンプルと `index.html` 直接起動での確認手順を記載する。

### 保存データとの互換性

- [ ] セーブ機能を実装する前に、定義IDの変更・削除時の扱いと定義データのバージョン管理を決める。

## P0完了の目安

上記のコンテンツ定義・検証ルールと追加手順を決め、起動時検証へ反映したら、保存データ互換性以外のP0を完了とします。保存データ互換性はセーブ機能の設計時に扱います。
